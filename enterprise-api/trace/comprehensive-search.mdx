## **Comprehensive Search (Efficient)**

A fixed search profile that compares songs on three independent signals at once, so you can judge similarity from more than one angle:

1.  **Full mix**: the whole track.
2.  **Vocals and accompaniment**: each compared separately.
3.  **Melody**: melodic phrases in the vocals and in the other instruments.

It is designed for screening work such as copyright checks, where one score on its own is not enough. You do not choose depths; the profile decides them.

*   <Method type="POST">POST</Method> `/trace/v3/comprehensive1`

<Note>
  For `1:n` and `m:n`, the datasets must be ingested with `track`, `light_stem` and `motif`. That is the [default ingestion](/enterprise-api/trace/ingest#depths-and-what-they-prepare), so a dataset ingested without a `depth` is ready. A `1:1` search needs no ingestion.
</Note>

<Tip>
  For a deeper check that also compares structure, every instrument, lyrics and style, use the [Comprehensive – Deep use case](/enterprise-api/trace/use-case-search) (`POST /trace/v3/comprehensive2`).
</Tip>

### **Request Body Fields**

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `search_type` | string | ✅ | `"1:1"`, `"1:n"` or `"m:n"` |
| `query_file_id` | string | 1:1, 1:n | `file_id` of the song you are checking |
| `candidate_file_id` | string | 1:1 | `file_id` of the song to compare against |
| `candidate_dataset_name` | string | 1:n, m:n | Name of the dataset to search |
| `query_dataset_name` | string | m:n | Name of the dataset whose songs are the queries |
| `limit` | integer | | Maximum number of matches returned per query song |
| `budget_tokens` | integer | | Optional cap on what this job may cost. See [Errors & Billing](/enterprise-api/trace/errors-and-billing#budget-cap) |
| `query_url`, `candidate_url` | string | | Legacy alternatives to the file IDs: `blob_name` values from [`/trace/v3/upload`](/enterprise-api/trace/upload#legacy-upload) |

### **Request Example**

<CodeGroup>
```bash cURL
curl -X POST "https://apiv2.soundverse.ai/trace/v3/comprehensive1" \
  -H "Authorization: Bearer sksoundverse_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "search_type": "1:n",
    "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
    "candidate_dataset_name": "reference-catalog"
  }'
```

```python Python
import requests

resp = requests.post(
    "https://apiv2.soundverse.ai/trace/v3/comprehensive1",
    headers={"Authorization": "Bearer sksoundverse_your_api_key"},
    json={
        "search_type": "1:n",
        "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
        "candidate_dataset_name": "reference-catalog",
    },
)
job_id = resp.json()["job_id"]
```
</CodeGroup>

## **What the Results Contain**

Each match carries a `summary` with the three signals side by side, and is ranked by `score`, the full-mix headline score.

```json
{
  "id": "b3ea82b7b97c8e2f733cd7850d12db41f4f334aa59c88cdd09538c3554d28326.mp3",
  "score": 0.636743,
  "percentage": 63.67,
  "summary": {
    "full_audio_hungarian_mean": 0.636743,
    "full_audio_max_then_mean": 0.69,
    "full_audio_max": 0.81,
    "vocal_hungarian_mean": 0.58,
    "vocal_max_then_mean": 0.62,
    "vocal_max": 0.77,
    "motif_matches_vocals_count": 2,
    "motif_matches_other_count": 5
  },
  "full_audio_latent_scores": { },
  "vocal_latent_scores": { },
  "instrumental_latent_scores": { },
  "motif_matches": { }
}
```

| Field | Description |
| :--- | :--- |
| `full_audio_*` | Similarity of the full mix |
| `vocal_*` | Similarity of the separated vocals |
| `instrumental_latent_scores` | Similarity of the accompaniment |
| `motif_matches_vocals_count`, `motif_matches_other_count` | How many melodic phrases matched in the vocals and in the other instruments |

The full blocks (`full_audio_latent_scores`, `vocal_latent_scores`, `instrumental_latent_scores`, `motif_matches`) carry the per-window detail. See [Reading the Results](/enterprise-api/trace/search-status#reading-the-results).

<Note>
  If a dataset is missing one of the required layers, the job still completes, but `results.error` names what is missing. Ingest the missing layers and run the search again.
</Note>

<Note>
  `m:n` comprehensive results are often larger than 200 KB. In that case the job response points to [Full Results](/enterprise-api/trace/job-results).
</Note>
