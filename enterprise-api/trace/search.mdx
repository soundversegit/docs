## **Custom Search**

Run a similarity search at the depths you choose. The request returns a `job_id` immediately; poll it with [Job Status & Results](/enterprise-api/trace/search-status).

*   <Method type="POST">POST</Method> `/trace/v3/search`

<Tip>
  Not sure which depths to pick? [Comprehensive Search](/enterprise-api/trace/comprehensive-search) and the [Use-Case Searches](/enterprise-api/trace/use-case-search) choose them for you.
</Tip>

### **Request Body Fields**

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `search_type` | string | ✅ | `"1:1"`, `"1:n"` or `"m:n"` |
| `query_file_id` | string | 1:1, 1:n | `file_id` of the song you are checking |
| `candidate_file_id` | string | 1:1 | `file_id` of the song to compare against |
| `candidate_dataset_name` | string | 1:n, m:n | Name of the dataset to search |
| `query_dataset_name` | string | m:n | Name of the dataset whose songs are the queries |
| `depth` | string or string[] | | Layers to compare. Defaults to `["track"]`. See [Depth values](#depth-values) |
| `stem_types` | string[] | | Instruments to compare when `depth` includes `stem` or `stem_section`: `vocals`, `bass`, `drums`, `other`. Defaults to `["vocals"]` |
| `limit` | integer | | Maximum number of matches returned per query song (1:n and m:n). Must be 1 or more |
| `budget_tokens` | integer | | Optional cap on what this job may cost. See [Errors & Billing](/enterprise-api/trace/errors-and-billing#budget-cap) |
| `query_url` | string | | Legacy alternative to `query_file_id`: a `blob_name` from [`/trace/v3/upload`](/enterprise-api/trace/upload#legacy-upload) |
| `candidate_url` | string | | Legacy alternative to `candidate_file_id`: a `blob_name` |

<Note>
  If you send both a file ID and a `blob_name` for the same side, the file ID is used. Full URLs are never accepted as song inputs; upload the file with [`POST /v1/files`](/enterprise-api/trace/upload) and pass its `file_id`.
</Note>

### **Depth Values**

| `depth` | Compares | The dataset must have |
| :--- | :--- | :--- |
| `track` | The full mix | `track` |
| `light_stem` | Vocals and accompaniment, separately | `light_stem` |
| `stem` | The instruments listed in `stem_types`, separately | `stem` |
| `section` | Matching song sections | `section` |
| `stem_section` | Sections within each instrument in `stem_types` | `stem` and `section` |
| `motif` | Melodic phrases | `motif` |
| `lyrics` | Transcribed lyrics | `lyrics` |
| `translation` | Lyrics after translating both songs to English | `translation` |
| `insights` | Genre, instrument and style tags | `insights` |

You can combine several depths in one search, for example `["track", "section", "lyrics"]`. For `1:n` and `m:n`, the candidate dataset (and, for `m:n`, the query dataset) must have been [ingested](/enterprise-api/trace/ingest) with every depth you request. A `1:1` search needs no ingestion.

<Note>
  `lyrics`, `translation` and `insights` need `file_id` inputs, because Trace looks up each song's lyrics and tags through its file. You can send a search with only text depths to compare lyrics or style without any audio layer.
</Note>

## **Search Shapes**

### **1. One song against one song (`1:1`)**

<CodeGroup>
```bash cURL
curl -X POST "https://apiv2.soundverse.ai/trace/v3/search" \
  -H "Authorization: Bearer sksoundverse_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "search_type": "1:1",
    "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
    "candidate_file_id": "0190a1b2-0001-7000-8000-00000000a001",
    "depth": ["track"]
  }'
```

```python Python
import requests

resp = requests.post(
    "https://apiv2.soundverse.ai/trace/v3/search",
    headers={"Authorization": "Bearer sksoundverse_your_api_key"},
    json={
        "search_type": "1:1",
        "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
        "candidate_file_id": "0190a1b2-0001-7000-8000-00000000a001",
        "depth": ["track"],
    },
)
job_id = resp.json()["job_id"]
```
</CodeGroup>

### **2. One song against a dataset (`1:n`)**

```json Request Body
{
  "search_type": "1:n",
  "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
  "candidate_dataset_name": "reference-catalog",
  "depth": ["track", "section", "lyrics"],
  "limit": 10
}
```

### **3. A dataset against a dataset (`m:n`)**

Every song in the query dataset is compared with every song in the candidate dataset.

```json Request Body
{
  "search_type": "m:n",
  "query_dataset_name": "new-releases",
  "candidate_dataset_name": "reference-catalog",
  "depth": ["track"]
}
```

### **4. Choosing instruments**

Compare the bass and drums separately, for example to look for a lifted groove:

```json Request Body
{
  "search_type": "1:n",
  "query_file_id": "0190a1b2-0003-7000-8000-00000000a003",
  "candidate_dataset_name": "reference-catalog",
  "depth": ["stem"],
  "stem_types": ["bass", "drums"]
}
```

## **Response**

**Status 201 Created**
```json
{
  "job_id": "0190a1c0-2222-7000-8000-000000000102",
  "status": "queued"
}
```

Poll [`GET /trace/v3/jobs/{job_id}`](/enterprise-api/trace/search-status) until `status` is `completed` to read the scores.

## **Errors**

All validation errors return `422`, and nothing is queued or charged.

| Message | Cause |
| :--- | :--- |
| `search_type must be one of '1:1', '1:n', 'm:n'` | `search_type` is missing or invalid |
| `a 1:1 search needs both a query and a candidate track (…)` | A `1:1` search is missing one of its songs |
| `a 1:n search needs a query track and candidate_dataset_name` | A `1:n` search is missing the query song or the dataset |
| `an m:n search needs query_dataset_name and candidate_dataset_name` | An `m:n` search is missing a dataset |
| `unknown depth 'x'` | A `depth` value is not in the table above |
| `stem_types takes vocals, bass, drums and other` | A `stem_types` value is not one of the four instruments |
| `limit must be an integer >= 1` | `limit` is zero, negative or not a whole number |
| `query_url takes a blob_name from /trace/v3/upload, not a url. …` | A full URL was passed as a song input |

A search that names a dataset you do not have, or a depth the dataset was not ingested with, is accepted but finishes as `failed` with an explanation in `error`. You are not charged for it. For authentication, balance and rate-limit errors, see [Errors & Billing](/enterprise-api/trace/errors-and-billing).
