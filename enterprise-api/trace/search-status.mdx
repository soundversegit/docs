## **Get Job Status**

Returns the status of any Trace job (custom search, comprehensive search, use-case search or ingestion) and its results once it has completed. Polling is **free**.

*   <Method type="GET">GET</Method> `/trace/v3/jobs/{job_id}`

### **Path Parameters**

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `job_id` | string | ✅ | The `job_id` returned when the job was created |

```bash cURL
curl "https://apiv2.soundverse.ai/trace/v3/jobs/0190a1c0-2222-7000-8000-000000000102" \
  -H "Authorization: Bearer sksoundverse_your_api_key"
```

### **Response Envelope**

```json
{
  "success": true,
  "data": {
    "job_id": "0190a1c0-2222-7000-8000-000000000102",
    "status": "completed",
    "error": null,
    "results": { }
  }
}
```

| Field | Description |
| :--- | :--- |
| `data.status` | `pending`, `processing`, `completed` or `failed` |
| `data.error` | Why the job failed, when `status` is `failed`. Otherwise `null` |
| `data.results` | The scores. Present once the job has completed |
| `data.results_complete` | Present and `false` when the result was too large to include. See [Large results](#large-results) |
| `data.results_url` | Present with `results_complete`. The path to fetch the full result from |

### **Job Status Values**

| `status` | Meaning |
| :--- | :--- |
| `pending` | Queued, waiting for a worker |
| `processing` | Running |
| `completed` | Finished successfully. Read `results` |
| `failed` | Did not finish. Read `error`. You are not charged |

## **Polling**

Most searches finish within seconds to a few minutes. A `1:1` search over many layers takes longest, because both songs are analysed on the spot. Poll every 5 to 15 seconds.

```python Python
import time
import requests

API = "https://apiv2.soundverse.ai"
HEADERS = {"Authorization": "Bearer sksoundverse_your_api_key"}


def wait_for_job(job_id: str, interval: float = 10.0) -> dict:
    while True:
        data = requests.get(f"{API}/trace/v3/jobs/{job_id}", headers=HEADERS).json()["data"]
        if data["status"] == "completed":
            if data.get("results_complete") is False:
                return requests.get(f"{API}{data['results_url']}", headers=HEADERS).json()
            return data["results"]
        if data["status"] == "failed":
            raise RuntimeError(data["error"])
        time.sleep(interval)
```

## **Reading the Results**

Every layer reports three scores between `0` (no similarity) and `1` (identical):

| Score | Meaning |
| :--- | :--- |
| `hungarian_mean` | **The headline score.** Trace cuts each song into 16 windows of 8 seconds and pairs every window with its best one-to-one partner; this is the average of those pairs |
| `max_then_mean` | Each window's closest match, averaged. Several windows may share a partner |
| `max` | The single most similar pair of windows |

`percentage` is the ranking score multiplied by 100. Melody (`motif`) results report numbers of matching phrases rather than a percentage.

<Note>
  Results may include more fields than are shown here, such as per-window details (`score_matrix`, `matched_windows`). Read the fields you need and ignore the rest; new fields can be added over time.
</Note>

### **`1:1` result**

The scores for the requested layers, for example `full_audio_latent_scores` for `depth: ["track"]`:

```json
{
  "status": "success",
  "search_type": "1:1",
  "depth": "track",
  "full_audio_latent_scores": {
    "hungarian_mean": 0.576373,
    "max_then_mean": 0.636297,
    "max": 0.725281,
    "matched_windows": [
      {
        "query_index": 3,
        "candidate_index": 5,
        "similarity_score": 0.725281,
        "query_audio_timestamps": [24.0, 32.0],
        "candidate_audio_timestamps": [40.0, 48.0]
      }
    ],
    "score_matrix": [[0.51, 0.48, "…"], "…"]
  }
}
```

`matched_windows` shows which moments of the two songs line up (start and end, in seconds).

### **`1:n` result**

`matches` lists every song in the dataset, most similar first:

```json
{
  "status": "success",
  "search_type": "1:n",
  "depth": "track",
  "candidate_dataset_id": "8e7d6c5b-4a39-4281-9706-f5e4d3c2b1a0",
  "matches": [
    {
      "id": "d79efad889c32e5537210f024e073632ec65fb9b5feb8576e91cad7c2bdc0466.mp3",
      "score": 1.0,
      "percentage": 100.0,
      "payload": { "filename": "d79efad889c32e5537210f024e073632ec65fb9b5feb8576e91cad7c2bdc0466.mp3", "dataset_id": "8e7d6c5b-4a39-4281-9706-f5e4d3c2b1a0" },
      "full_audio_latent_scores": { "hungarian_mean": 1.0, "max_then_mean": 1.0, "max": 1.0 }
    },
    {
      "id": "b3ea82b7b97c8e2f733cd7850d12db41f4f334aa59c88cdd09538c3554d28326.mp3",
      "score": 0.636743,
      "percentage": 63.67,
      "payload": { "filename": "b3ea82b7b97c8e2f733cd7850d12db41f4f334aa59c88cdd09538c3554d28326.mp3", "dataset_id": "8e7d6c5b-4a39-4281-9706-f5e4d3c2b1a0" },
      "full_audio_latent_scores": { "hungarian_mean": 0.636743, "max_then_mean": 0.69, "max": 0.81 }

```

<Tip>
  Each match's `id` is Trace's audio ID. To find which of your files it is, look it up in [`GET /trace/v3/dataset/{dataset_id}/tracks`](/enterprise-api/trace/datasets#list-dataset-tracks): the track with that `audio_id` carries your `file_id` as `source_ref`.
</Tip>

### **`m:n` result**

`results` holds one entry per query song, each with its own `matches` list:

```json
{
  "search_type": "m:n",
  "depth": "track",
  "query_dataset_id": "1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "candidate_dataset_id": "8e7d6c5b-4a39-4281-9706-f5e4d3c2b1a0",
  "results": [
    {
      "query_audio_id": "e017cb015b32….mp3",
      "matches": [
        { "id": "b3ea82b7b97c….mp3", "score": 0.71, "percentage": 71.0 },
        { "id": "d79efad889c3….mp3", "score": 0.62, "percentage": 62.0 }
      ]
    }
  ]
}
```

### **Multiple layers**

When you request several depths, each layer adds its own block next to the others:

| Depth | Result block |
| :--- | :--- |
| `track` | `full_audio_latent_scores` |
| `light_stem` | `vocal_latent_scores`, `instrumental_latent_scores` |
| `stem` | per-instrument scores; a `1:n` search with only `stem` groups its matches by instrument in `matches_by_stem` |
| `section` | `section_breakdown` |
| `motif` | `motif_matches` |
| `lyrics`, `translation` | `lyrics_similarity`, `translation_similarity` |
| `insights` | `tag_overlap` |

 Matches are ranked by the first available layer in this order: `track`, `light_stem`, `stem`, `section`, `stem_section`, `motif`.

## **Large Results**

When a result is larger than about 200 KB (common for `m:n` searches over several layers), it is not included in the job response. Instead you get:

```json
{
  "success": true,
  "data": {
    "job_id": "0190a1c0-5555-7000-8000-000000000105",
    "status": "completed",
    "error": null,
    "results": {},
    "results_complete": false,
    "results_url": "/trace/v3/jobs/0190a1c0-5555-7000-8000-000000000105/results"
  }
}
```

Fetch the full result from `results_url`. See [Full Results](/enterprise-api/trace/job-results).

## **Errors**

**Status 404 Not Found** when the job does not exist or belongs to another account. The two cases return the same response.
```json
{
  "error": "ResourceNotFound",
  "message": "job not found",
  "retryable": false
}
```
