## Guide scope

This guide explains the current Soundverse DNA creation and use flows.

It covers:

- Full Production DNA

- Voice DNA

- DNA models and track references

- Processing and training states

- Visibility and public discovery

- Earn and Stripe Connect boundaries

- Common troubleshooting steps

The guide describes the current product behavior.

It does not replace Soundverse terms, license terms, or financial advice.

## Quick decision

Use **Full Production DNA** when you want to train from a catalog of songs, instrumentals, or acapellas.

Use **Voice DNA** when you want to train from clean solo-vocal recordings.

Do not use Voice DNA as a shortcut for a mixed music catalog.

Do not use Full Production DNA as a shortcut for cloning a particular person's voice.

Only upload material that you own or are authorized to use.

For Voice DNA, you must also be the speaker or have the singer's consent.

## Product map

The DNA area contains several related surfaces.

They have different purposes.

### My DNA

My DNA is the main management area for your own DNA work.

Use it to inspect your primary DNA, models, tracks, and voice models.

It is the place to return after a Full Production processing run or Voice DNA training run.

Treat the current in-product state in My DNA as the source of truth for your result.

### Discover

Discover is for browsing DNA content that is eligible for public discovery.

Public visibility alone does not make a DNA discoverable.

The current Full Production public path requires both Public visibility and Approved status.

### Earn

Earn contains the current Stripe Connect flow where creator earnings are available.

It can show a connection state and the DNA dashboard summary available for the connected account.

It does not independently guarantee royalties, payout dates, eligibility, or commercial rights.

### Generation

The DNA generation experience uses an available DNA model or track reference.

The controls change according to the selected DNA, model, and reference.

Use the controls that the product enables for the current selection.

## Core concepts

### DNA

DNA is a Soundverse creator profile built from audio.

It provides source material that Soundverse can process into DNA models and track references.

The number and type of resulting assets vary with the supplied material and processing outcome.

### Primary DNA

The current Full Production flow uses one primary DNA profile per owner.

That profile is the ongoing home for the creator's catalog-based DNA.

Later uploads and processing runs add to the same primary DNA.

They do not create another primary Full Production DNA profile for the same owner.

### Full Production DNA

Full Production DNA is the catalog-based flow.

It accepts songs, instrumentals, and acapellas.

It processes the catalog into available music-style models and track references.

Use it when the goal is to represent a broader musical identity or catalog.

### Voice DNA

Voice DNA is the voice-focused flow.

It accepts clean solo-vocal recordings and trains a voice model.

In the current primary workflow, the trained voice model is added to the creator's primary DNA profile.

It does not remove or replace existing Full Production catalog material.

### DNA model

A DNA model is an available processed model associated with a DNA.

When the product presents it, it can be selected as a broader starting point for generation.

Model availability depends on processing and on the current DNA.

### Track reference

A track reference is an available processed audio reference associated with a DNA.

The product can show song, vocal, or instrumental reference types.

A track reference can narrow the starting point for available generation.

It does not guarantee that every generation control is supported.

### Generation style

The current DNA generation contract supports two request styles:

- Song

- Instrumental

The interface can show vocal references.

That does not make vocal a separate universal generation style.

## Part 1: Prepare before creating DNA

### 1. Decide which flow you need

Start by deciding what you want the DNA to represent.

Choose Full Production DNA for a music catalog.

Choose Voice DNA for one person's voice.

Do not mix the two goals together without understanding which flow owns the training request.

### 2. Confirm authorization

Before selecting any files, confirm that you have the necessary authority to upload them.

For Full Production DNA, the current upload form asks you to confirm ownership and authority to upload the files.

For Voice DNA, the form asks you to confirm that the voice is yours or that you have the singer's consent.

Do not submit a confirmation you cannot truthfully make.

### 3. Keep the original source files

Keep a local copy of every selected audio file until the upload and processing state are clear.

This makes retrying an upload easier if a transfer is interrupted.

It also helps you identify exactly which material was included when you contact support.

### 4. Prepare a focused Full Production catalog

Use songs, instrumentals, or acapellas that represent the sound you want the DNA to learn.

The source collection does not need to be enormous to be useful.

It should be intentional.

A coherent catalog is generally easier to reason about than unrelated audio selected only to raise the file count.

### 5. Prepare clean Voice DNA recordings

Aim for at least 10 minutes of clean solo-vocal audio.

Use one speaker or singer only.

Avoid background music and heavy effects.

The voice trainer can re-slice recordings.

You do not need to pre-cut every source recording into small clips before upload.

### 6. Choose a clear name

Give the primary DNA or voice profile a name you can recognize later.

The name should help distinguish the creator or voice model in My DNA.

Avoid relying on a vague temporary name when you expect to create several models or return later for follow-up training.

### 7. Prepare short profile copy

The current profile-description inputs are limited to 300 characters.

Prepare a concise description that helps identify the DNA.

Use tags to summarize the musical identity or profile context.

Tags help organize the product experience but do not guarantee a specific generated result.

### 8. Choose an initial visibility intentionally

Full Production DNA and Voice DNA do not present exactly the same visibility controls.

For Full Production DNA, the current choices are Public, Private, and Personal.

For Voice DNA, the current form presents private and public.

Use a non-public setting while you are training or testing if you do not want the DNA considered for public visibility.

## Part 2: Full Production DNA

### Overview

Full Production DNA is the primary catalog-based flow.

It has five current steps:

1. Profile Settings

2. Upload Section

3. Process DNA

4. Advanced

5. Finalize

The primary DNA relationship is important.

The current flow starts from your one primary DNA profile.

New catalog audio and newly processed results are added to that profile over time.

### Step 1: Open the primary profile

Open the Full Production DNA flow from the DNA area.

The app retrieves or creates the canonical primary DNA profile for the current owner.

This is why the flow does not create a second primary profile for the same owner.

Existing legacy DNA entries can still be visible for some accounts.

The current Full Production creation path remains focused on the primary DNA.

### Step 1: Complete Profile Settings

The first Full Production panel is the profile area.

Use it to identify the primary DNA before uploading more source material.

The current fields include creator name, description, tags, and cover art.

<img
  src="/images/create/dna/02-full-production-profile-settings.png"
  alt="Full Production DNA Profile Settings step with the five-step rail, profile fields, tags, and cover controls"
/>

### Creator name

Enter a name that clearly identifies the profile.

This is the name you will see again when managing the DNA.

Use a stable creator or project name rather than an ambiguous file label.

### Description

The Full Production description is limited to 300 characters in the current form.

Use it to explain the DNA in a compact way.

It is better to describe the broad musical purpose than to promise a result that processing cannot guarantee.

### Tags

The profile area offers suggested tags and a tag input.

Use tags to describe the catalog or creative direction.

Examples of useful tag themes include genre, mood, instrumentation, era, or production character when they are actually relevant to the uploaded work.

Tags are metadata.

They are not a promise that a corresponding model or output style will be created.

### Cover art

The Full Production profile includes cover-art controls.

Use a cover image when you want to make the primary DNA easier to recognize.

The cover art does not replace the audio catalog.

Full Production processing uses the uploaded music files rather than the cover image.

### Check the profile before continuing

Before moving to Upload Section, confirm:

- The creator name is recognizable

- The description is concise and accurate

- The tags make sense for the catalog

- The cover image is appropriate if you chose one

This keeps the ongoing primary profile easier to manage after future uploads.

### Step 2: Upload Section

Use Upload Section to add audio for Full Production DNA processing.

The current flow accepts at least one audio file.

The current maximum is 1,000 audio files.

The upload text does not require a minimum duration for Full Production audio.

<img
  src="/images/create/dna/03-full-production-upload-section.png"
  alt="Full Production DNA Upload Section showing accepted catalog guidance, a selected audio file, and the step rail"
/>

### Full Production accepted formats

The current Full Production file input accepts:

- .mp3

- .wav

- .aac

- .ogg

- .flac

- .m4a

Select actual audio files in one of those formats.

Do not attempt to upload a document, image, archive, or video file through this audio input.

### Full Production source categories

You can use:

- Songs

- Instrumentals

- Acapellas

These are catalog source categories.

They are not the same thing as the two DNA generation request styles.

The generation request contract later supports Song and Instrumental.

### Ownership confirmation

The Full Production upload step includes an ownership-and-authority confirmation.

Read it before continuing.

Confirm it only when you have the authority to include every selected file.

If even one file is unclear, remove it until you resolve the rights question.

### Choose a useful catalog

Choose files that represent the intended DNA sound.

The product can process varied catalog material, but results can vary when source audio has no clear connection.

Do not expect a guaranteed number of models or track references from a particular file count.

The collection's relevance matters more than a raw file total.

### Watch upload progress

The current Full Production uploader reports progress as it transfers the selected files.

Wait for the upload flow to confirm that the selected audio is ready before trying to process it.

Do not treat a file-selection action as proof that the file is fully uploaded.

<img
  src="/images/create/dna/04-full-production-upload-progress.png"
  alt="Full Production DNA upload progress for a selected audio file"
/>

### Temporary interruption and retry

The current Full Production uploader uses an upload session and local checkpoints.

When the session remains valid, it can reuse confirmed chunks instead of blindly restarting every file transfer.

If a temporary network problem appears, retry with the same files.

Keep the source files in place until the product confirms completion.

### When a session cannot resume

An upload session can expire or become invalid.

In that case, the uploader can request a new server-issued session.

This is expected recovery behavior.

It does not mean that the previous session should be treated as a completed upload.

### When the upload reports an error

Read the error message before taking the next action.

Check that the selected files are accepted audio formats.

Keep the file list available.

Retry the same selection once the product allows it.

If the failure persists, capture the error text, time, and number of files for support.

### Do not process incomplete uploads

Processing requires audio that is ready to process.

Do not click Process DNA as soon as files are selected if the uploader is still transferring them.

Wait until the upload UI indicates that the source material has completed its upload path.

### Step 3: Process DNA

Process DNA is the step that starts Full Production model processing.

It is not merely a review screen.

The primary flow supplies the selected sensitivity and the newly uploaded audio to the processing request.

Use this step only after the upload is ready.

### Full Production sensitivity

The current sensitivity slider ranges from 0 to 10.

The default value is 5.

The UI describes lower sensitivity as creating broader genre DNA results.

It describes higher sensitivity as creating more niche style DNA results.

<img
  src="/images/create/dna/05-full-production-sensitivity.png"
  alt="Full Production DNA Process DNA sensitivity control set to the balanced value of 5"
/>

### Choosing a lower sensitivity

Choose a lower sensitivity when the goal is broader genre-style grouping.

This is a creative configuration choice.

It does not create a separate primary DNA profile.

It does not promise that a particular broad genre name will appear in the result.

### Choosing the default sensitivity

The current default is 5.

The interface presents that central value as the balanced choice.

It is a reasonable place to begin when you do not have a clear reason to prefer broader or more niche grouping.

### Choosing a higher sensitivity

Choose a higher sensitivity when you want the catalog processed toward more niche style DNA results.

Higher sensitivity is not a guarantee that each source track becomes its own style model.

The actual results still depend on the processed catalog.

### Start processing once

The current primary flow prevents a second processing start while DNA processing is already active for the same DNA.

If the UI says processing is already running, wait for the active run to complete.

Do not repeatedly launch duplicate attempts while the first run is still active.

### What happens to earlier results on a later run?

The current primary processing path is additive.

It preserves existing core playlists rather than clearing them before re-clustering.

Later uploads can add new models and track results to the primary DNA.

The earlier content is intended to remain in place.

### What Process DNA does not promise

It does not promise:

- A fixed completion time

- A fixed model count

- A fixed track count

- Every possible reference type

- A specific genre or tag

Treat the processing result as data derived from the uploaded catalog.

### Step 5: Finalize

Finalize is the final part of the Full Production creation interface.

The primary flow starts catalog processing from Process DNA before Finalize.

Use Finalize to complete the current configuration and review experience.

Do not assume that Finalize restarts processing if processing has already begun.

### After Finalize

Return to My DNA to inspect the current result.

The product can add model and track results to the primary DNA as processing completes.

Results can appear as available models, tracks, or voice-related content in the management experience.

### Model-ready email

Soundverse attempts to send a model-ready email after a full-production model run has persisted results.

Email is best effort.

The model result is queryable in the product before an email delivery issue can affect it.

If the email does not arrive, check My DNA rather than assuming the model failed.

### When you can leave the page

Once Full Production processing has started, you can leave the page and return later.

The current product flow continues the processing work independently of keeping the creation view open.

My DNA is the right place to inspect the outcome later.

## Part 3: What Full Production processing can create

### Models

Full Production processing can add music-style models to the primary DNA.

The models available for a DNA are driven by the processing result.

One catalog can produce a different model result from another catalog.

Do not promise a specific count before the processing result is available.

### Track references

Processing can associate track references with the primary DNA.

The interface can represent available source references as song, vocal, or instrumental.

Those are reference categories.

They are not a universal set of final generation buttons.

### Tags and classifications

The processing pipeline can persist style-related tags and source classification information for uploaded audio.

The final information available in the UI can vary.

Avoid promising tempo, musical key, energy, era, or an exact style description unless the current product explicitly shows it for the selected result.

### When no separate style model appears

Do not assume that every catalog will produce several separate style models.

The system can retain a usable primary model path even when style clustering does not yield multiple usable style results.

Inspect My DNA for what was actually created.

### Adding more catalog material later

Use the existing primary DNA when you have more authorized catalog material.

Upload the new files.

Wait for the upload to become ready.

Start a new processing run when no previous run is active.

Review the new state in My DNA.

### Select a DNA

Open the available DNA generation experience.

Choose a DNA that is available to you.

The list of available models and track references depends on that DNA and the product state.

### Select a model or track reference

When the UI presents both options:

- Choose a model for a broader DNA starting point

- Choose a track reference for a more specific starting point

The product decides which controls are available for the chosen context.

### Understand context-aware controls

DNA generation controls are not identical for every model or track.

They depend on the selected DNA, available model, and selected reference.

Use the controls that are enabled.

If a control is missing or disabled, it is not currently supported for that selection.

### Song and Instrumental

The current DNA generation contract accepts Song and Instrumental styles.

Song refers to the available song-generation path.

Instrumental refers to the available instrumental-generation path.

The product may map an available reference to one of those supported request styles.

### Vocal references

A reference can be categorized as vocal.

That does not mean the generation backend accepts a separate vocal or acapella request style.

Do not promise a standalone vocal output from every vocal reference.

Use the options currently enabled in the UI.

### Input text

When a music description or lyrics field is presented, provide text that matches the enabled flow.

The exact available input fields depend on the current product selection.

Keep expectations tied to the visible controls and current DNA result rather than a generic feature matrix.

### If generation controls change

Changing the selected DNA, model, or track reference can change the controls.

This is expected context-aware behavior.

Try another available reference only when it matches your intended musical starting point.

## Part 5: Voice DNA

### Overview

Voice DNA is a dedicated training flow for one person's voice.

It has five current steps:

1. Voice Profile

2. Upload Recordings

3. Settings

4. DNA Quality

5. Finalize

The Start Training control is on DNA Quality.

Finalize then displays the training state.

### Voice source requirements

Use solo-vocal recordings.

Aim for at least 10 minutes of clean voice audio.

Use one speaker or singer only.

Avoid background music and heavy effects.

The cleaner and more representative the source material is, the clearer the training intent.

### Voice consent requirement

The current Voice DNA form requires a consent checkbox.

The checkbox confirms that the voice is yours or that you have the singer's consent to clone it.

The upload step cannot validate without that confirmation.

Do not bypass or misrepresent the consent requirement.

### Step 1: Voice Profile

The Voice Profile area includes:

- Creator Name

- Description

- Tags

- Cover image upload

- Avatar selection

The current description field is limited to 300 characters.

<img
  src="/images/create/dna/11-voice-profile.png"

### Voice profile naming

Use a name that lets you identify the voice model later.

The training flow generates a model name based on the profile context and the next voice-model number.

You do not need to manually invent an internal numbered model name.

### Existing and primary profile context

The Voice DNA UI has a profile step.

In the current primary mode, the voice model is added to the canonical primary DNA.

Existing DNA content stays unchanged.

Follow the profile context shown in the product when you start the flow.

### Step 2: Upload Recordings

Use Upload Recordings to add voice material.

The form requires at least one recording.

The product guidance says to aim for at least 10 minutes of clean solo-vocal audio.

The two points are different:

- One recording satisfies the basic form requirement

- A useful voice dataset should follow the guidance

The current Voice DNA file input accepts:

### Add existing audio files

Use the Select audio files action or drag files into the upload area.

### Record in the product

The Voice DNA upload area includes a Record action.

It can be used when the device and browser permit recording.

Review the resulting audio before using it as training material.

### Upload status

The Voice DNA uploader reports progress and status.

It can report that recordings are being packaged.

If it reports an upload error, read the error text and retry only after checking the files and consent.

### Consent before moving forward

The Voice DNA upload step validates two required conditions:

- At least one recording is selected

- The consent checkbox is selected

If either condition is missing, the flow directs you to fix it before training.

### Step 4: DNA Quality

DNA Quality is the Voice DNA configuration step.

It uses epoch count rather than the Full Production sensitivity slider.

The current UI labels the quality range as:

- Fast at 10 epochs

- Balanced at about 180 epochs

- Studio at 350 epochs

It describes 40 to 200 epochs as typical.

### What higher Voice quality means

The current UI describes more epochs as seeking a higher-fidelity clone while taking longer to train.

Higher is not automatically better for every recording set.

Use the balanced default when you do not have a source-specific reason to choose another value.

### Estimates in the Voice quality panel

The quality panel displays an estimated duration and token cost for the chosen epoch value.

Select Start Training from the DNA Quality step.

### Step 5: Voice Finalize

Finalize shows a summary of the Voice DNA.

It displays training progress and status after the request begins.

It provides a View in your profile action when the result is ready to inspect.

### Voice training states

The current Finalize view can show:

- Queued

- Preparing

- Training

- Completed

- Failed

### Queued

Queued means the Voice DNA request is waiting for available training capacity.

The current UI describes this as waiting for a GPU to become available.

Queued is not the same as failure.

### Preparing

Preparing means the system is packaging or processing the voice dataset before reported epoch progress is available.

The UI can show an indeterminate progress state during this phase.

This is not a reliable percentage completion estimate.

<img
  src="/images/create/dna/15-voice-dna-preparing.png"
  alt="Voice DNA Finalize screen showing the Preparing training state"
/>

### Training

When epochs are reported, the Finalize view shows training progress by current epoch and total epoch count.

The percentage is tied to that reported epoch progress.

Do not compare it directly to a guaranteed wall-clock completion time.

### Completed

Completed means the voice model reports completion.

The UI changes the status to say that the voice is ready.

Use View in your profile or My DNA to inspect the result.

### Failed

Failed means the current training result reported failure.

The UI reports the failure and directs the flow back to DNA Quality so you can try again.

Before retrying, review the source audio, consent, selected quality, and visible error text.

### Close the Voice DNA window

The current UI states that Voice DNA training continues if you close the window.

The result should appear under the profile's Voice DNAs when it is ready.

Return later to inspect the product state rather than keeping the window open only to watch progress.

## Part 6: Visibility, moderation, and discovery

### Visibility and status are separate

Full Production DNA visibility and moderation status are separate values.

Visibility tells the product whether the DNA is Public, Private, or Personal.

Status tells the product whether it is Pending, Approved, Rejected, or On hold.

One does not replace the other.

### Full Production public eligibility

For the current Full Production public discovery path, a DNA must be:

1. Public

2. Approved

If it is Private, Personal, Pending, Rejected, or On hold, it is not eligible for the public-discovery condition.

### Pending

Pending means the DNA has not reached the Approved state required for public discovery.

Do not share it as publicly discoverable until the product shows the required public eligibility.

This guide does not promise a review duration or outcome.

### Approved

Approved is the status required alongside Public visibility for current public discovery.

It does not change the need to comply with the applicable terms and rights requirements.

### Rejected or On hold

Rejected and On hold are statuses distinct from Approved.

Do not treat a Public visibility selection as sufficient to bypass those states.

Use the status actually shown in the product.

### Private and Personal

Private and Personal Full Production DNA are outside public discovery.

They are useful for setup, testing, and keeping the DNA out of the public browsing path.

Use the product's own visibility and status presentation when deciding how to share the DNA.

### Voice DNA visibility

The current Voice DNA form provides private and public options.

Use its specific visibility field rather than assuming it follows the Full Production visibility set exactly.

### Discover

Discover shows DNA content that is eligible for public discovery.

The available cards depend on the current visibility, moderation status, and product availability.

## Part 7: Earn and Stripe Connect

### Connect Stripe

The Earn section checks the current Stripe connection status.

When no connection is present, it offers a Connect Stripe action.

The action opens a Stripe Connect URL when the service returns one.

If it cannot open the connection request, the UI reports an error.

<img
  src="/images/create/dna/19-earn-connect-stripe.png"
  alt="Soundverse Earn screen before Stripe Connect is linked, showing Connect Stripe actions"
/>

### Connected account view

When Stripe reports that the account is connected, the Earn page can show data from the DNA dashboard summary.

The current UI can include lifetime earnings, recent earnings, usage, export data, and a path to the Stripe dashboard when that data is available.

The exact dashboard values depend on the connected account and returned summary.

### Where creator earnings come from

The Earn history records protected creator earnings from two current sources:

- **Paid DNA exports**: another creator completes a paid export for audio made with an eligible paid DNA.

- **Fan Support**: a fan completes a one-time or monthly Stripe support payment for a creator from an eligible conversation.

Creating a DNA, training a DNA, publishing a DNA, or generating audio does not by itself create a creator earning.

An entry is created only after the payment provider reports a verified payment through the relevant product flow.

The Earn balance is a creator-earnings ledger. It is not the same thing as the cash balance in a Stripe bank account.

### Paid DNA export earnings

When another creator pays to export audio made with a paid DNA, the current creator policy reserves **50% of the gross purchase payment** for the DNA creator.

For example, if the product records a $10.00 paid DNA export, the protected creator share is $5.00 before any later refund or dispute adjustment.

The buyer must complete the payment successfully. Opening a checkout page, closing it, or having a payment fail does not create an export earning.

The creator can see the source as **Paid DNA export** in the Earn history once the ledger has recorded it.

The price and license controls in the DNA experience can affect what is presented in the product, but they do not independently guarantee a sale, a ledger entry, a particular creator share, or a payout.

### Fan Support earnings

Fan Support is a direct support payment between people in an eligible Soundverse conversation. It is not a purchase of a DNA export and it does not grant ownership of the creator's work.

The current one-time Fan Support presets are $2, $5, $10, and $25 USD. The current monthly presets are $3, $8, and $20 USD.

For each verified Fan Support payment, the current creator policy reserves **75% of the gross support payment** for the recipient in the same protected creator-earnings ledger.

For example, a verified $5.00 one-time support payment reserves $3.75 for the recipient before any later refund, dispute, or reversal adjustment.

The platform records the creator's protected earning first. It does not attempt an immediate direct transfer to the recipient's Stripe account at the moment the fan pays.

### Can a creator earn before connecting Stripe?

Yes. A creator can have a protected earning recorded before they finish Stripe Connect onboarding.

That lets a verified paid DNA export or Fan Support payment appear in the creator's Earn history even when the creator has not yet linked a payout account.

Until Stripe setup is complete and the account is eligible, the balance cannot be sent as a payout. The history can show a note such as **Pending Stripe connection**, **Pending Stripe verification**, or **Payout setup required**.

Connecting Stripe later does not turn a protected balance into an instant bank transfer. The payment still needs to meet the normal protection, eligibility, threshold, and scheduling conditions described below.

### Connection states in Earn

Earn can show several Stripe connection states. The wording is meant to tell you what to do next:

- **Stripe not connected**: no payout account is linked yet. Earnings can still accrue, but a payout cannot be sent until you connect Stripe.

- **Setup incomplete**: a Stripe account is linked, but onboarding still has steps to complete.

- **Verification required**: Stripe needs more information before payments or payouts can be enabled.

- **Verification pending**: Stripe is reviewing the submitted information.

- **Payments restricted**: the linked account is not currently ready for payments or payouts. Review the Stripe setup for the specific requirement.

- **Stripe connected**: the account is linked and the product reports it as connected. Stripe can still impose account, country, identity, banking, and payout requirements.

Use the Stripe dashboard opened from Earn for account-specific requirements. Do not send Stripe login details, bank information, or identity documents through ordinary support messages.

### Read the balance cards

The cards in Earn describe different points in the creator-earnings lifecycle:

- **Current creator balance**: the current protected creator balance recorded by the ledger after known adjustments. It is not a bank balance and is not automatically withdrawable.

- **In payment protection**: earnings that are still inside the payment-protection period. They are intentionally held before becoming payout-eligible.

- **Eligible after protection**: earnings whose protection period has ended. They still require a ready Stripe account, the minimum payout threshold, and an active payout path.

- **Money accrued**: the running total of creator earnings that have been recorded in the ledger.

- **Money paid**: the running total of creator earnings that have been recorded as paid out. It does not include money that is only protected or eligible.

- **Historical paid-DNA estimate**: an analytics estimate that can appear in a live dashboard. It is not a replacement for the protected ledger balance or a promise of a future payout.

The exact set of cards can vary between sandbox and live mode, and when the protected ledger is temporarily unavailable.

### Understand the earning status in history

Each Earn history row identifies a source, date, status, and amount. The current status labels mean:

- **Payment protection**: the payment was recorded but remains inside the protection period.

- **Ready for payout**: the ledger marks the creator amount eligible after protection. It is still subject to payout setup and schedule checks.

- **Payout processing**: a payout is being processed against the ledger balance.

- **Paid**: the ledger has recorded the payout as completed.

- **Payment review**: the payment is being reviewed, such as after a refund or dispute event. The amount may be adjusted or reversed.

- **Payout setup required**: the earning is recorded, but Stripe connection, verification, banking, or another payout prerequisite must be completed first.

The history can also show a reversed amount. A reversal is an adjustment to the creator's earning after a verified refund, dispute, or other payment-provider event.

### Earning-to-payout lifecycle

The normal path is:

1. A buyer completes a paid DNA export or a fan completes a support payment.

2. The payment provider verifies the payment and the product records the creator's share in the protected ledger.

3. The earning remains in **Payment protection** for the applicable protection period.

4. The balance becomes **Ready for payout** when it is eligible, provided the payout setup is complete.

5. A qualifying scheduled payout moves through **Payout processing** and then **Paid** when the ledger records completion.

Not every payment reaches the final step. A refund, dispute, account restriction, missing payout setup, or unavailable payout schedule can change the status.

### Manage payouts

The connected Earn view provides a way to open Stripe for payout details, banking settings, and account requirements.

Use Stripe and the current product information to manage those details.

### Minimum payout threshold and next payout date

The live Earn view shows the current **Minimum payout threshold**. The current default displayed by the product is **$50 USD**, unless the configured account summary supplies a different amount.

Reaching the threshold is necessary but not sufficient for a payout. The amount must also be eligible after payment protection, the protected ledger must be available, and the Stripe account must be ready for payouts.

When automatic payouts are enabled for a live account, the current product schedule is eligible balances at or above the displayed threshold on the **28th of each month**. The **Next payout date** shown in Earn is the source of truth for the current account.

If Earn says **Not scheduled**, it can mean the balance has not met the conditions yet, automatic payouts are disabled, the account still needs Stripe setup, or the product cannot currently provide a payout schedule.

Stripe and the receiving bank can still take additional time to make a completed payout available. The displayed schedule is not a guarantee of bank-arrival time.

### When automatic payouts are disabled

Earn can continue tracking protected and eligible balances even when automatic payouts are disabled.

In that state, a visible balance is not an instruction to send a transfer yourself. It means the ledger has recorded creator earnings while the payout path is not automatically sending a transfer.

Check the current in-product payout message and Stripe account state rather than assuming that an eligible balance will move on a particular date.

### Test mode and live mode are separate

Soundverse uses separate Stripe environments for testing and live payments.

In **test or sandbox mode**, Stripe Connect and Checkout use Stripe test objects and test funds. Test earnings can be recorded in the sandbox ledger so the Earn flow can be validated, but test payouts are disabled and no real money is sent to a bank account.

In **live mode**, Stripe Connect and Checkout use live Stripe objects. Live earnings and live payouts are kept separate from sandbox data.

Do not mix a test Stripe account, test checkout URL, or test payment method with a live flow. A checkout created in one Stripe mode is not valid in the other.

### Refunds, disputes, and balance changes

An Earn balance can change after a payment is first recorded.

If a buyer receives a refund or a payment is disputed, the corresponding creator earning can move into **Payment review** or be reversed. A reversal can reduce the current balance and can affect an amount that had been waiting for payout.

This protection is intentional. It prevents a creator payout from being treated as final before the source payment is settled under the applicable payment rules.

### Monthly Fan Support

Monthly Fan Support uses a Stripe subscription rather than a one-time payment.

The current product prevents a supporter from creating duplicate active monthly support for the same creator. If an active pledge already exists, the supporter should manage that pledge instead of starting a second one.

Each successful monthly payment is handled as its own verified support payment for the creator-earnings ledger. A monthly pledge can change status when it is active, past due, canceling, canceled, expired, or unpaid.

Canceling a future monthly pledge does not automatically rewrite the status of support payments that were already verified. Check the current subscription and payment records in the product and Stripe.

### Important earnings boundary

Connecting Stripe does not itself promise:

- Payout eligibility

- A royalty amount

- A payout date

- A minimum balance

- A commercial right

- A successful DNA review

Those issues depend on the current product terms, license terms, account state, and Stripe requirements.

They can also depend on payment protection, the configured threshold, refunds or disputes, the availability of the protected ledger, and whether automatic payouts are enabled.

### What Earn does not replace

Earn is not a tax return, invoice system, tax advisor, legal advisor, or bank statement.

Stripe may request identity, business, bank, or tax information for the account. Provide accurate information directly to Stripe and seek qualified professional advice for tax, accounting, licensing, or legal questions that apply to you.

For a payment or payout issue, keep the non-sensitive details that help support investigate: the source shown in Earn, visible status, approximate time and timezone, amount, and any non-secret Stripe or Soundverse reference shown by the product.

## Part 11: Creator planning playbooks

This section turns the product concepts above into repeatable planning paths.

Use the playbooks to organize your own decisions before you upload, train, publish, generate, or connect a payout account.

They do not replace the current controls in Soundverse, the applicable terms, or the rights you need for your source material.

### How to use these playbooks

Pick the playbook that matches the outcome you want, then work through it in order.

Keep the key facts for each DNA project in a private project record: source-list summary, ownership or consent confirmation, selected settings, visible product status, and actual result.

Do not put passwords, Stripe details, session cookies, API keys, bank information, or private legal documents into a normal project note.

When a product state conflicts with an expectation, treat the current product state as the source of truth and use the troubleshooting sections before retrying.

### Playbook A: Choose the correct DNA route

Use this decision path before creating a new request.

#### A1. Define the real creative goal

Ask what you want the system to represent.

If the answer is a creator's broader musical catalog, production identity, songs, instrumentals, or authorized acapellas, start with **Full Production DNA**.

If the answer is one person's voice from clean solo-vocal recordings, start with **Voice DNA**.

Do not choose a route based only on the file extension or file name. Choose it based on the source material and the intended training goal.

#### A2. Separate catalog questions from voice questions

Full Production DNA can include vocal material as part of a music catalog.

That does not make it the voice-cloning flow.

Voice DNA is dedicated to the voice-focused request and requires that the source is one authorized speaker or singer.

If you need both a music catalog and a voice model, plan the source sets separately and use each flow only with the required rights and consent.

#### A3. Check who owns or controls the source material

For Full Production DNA, make sure you have the authority to upload the catalog material.

For Voice DNA, make sure the voice is yours or that you have the speaker's or singer's consent for this purpose.

Do not treat public availability, a streaming link, a social post, or a credit line as proof of training rights.

If you cannot make the product confirmation truthfully, do not submit the material.

#### A4. Make a simple source inventory

For each planned file, record:

- A clear local file name

- The original project or recording context

- The intended DNA flow

- Why the file belongs in that source set

- Whether you own it or have the needed authority or consent

- Whether it includes other voices, collaborators, samples, private speech, or sensitive material

This record helps you make a deliberate upload choice and gives you useful non-sensitive context if a support issue occurs later.

#### A5. Decide whether the material is focused enough

A Full Production catalog should reflect a meaningful creator or musical direction.

A Voice DNA dataset should reflect one person's clean voice.

If a file makes the goal harder to explain, contains unclear rights, or belongs to another person or project, leave it out until you can resolve that question.

More material is not automatically better than more relevant material.

#### A6. Choose a non-public starting state when appropriate

Use a non-public visibility choice while you are setting up, testing, or reviewing the DNA.

Full Production DNA currently uses Public, Private, and Personal visibility choices. Voice DNA currently presents private and public choices.

Visibility is separate from approval, so setting a Full Production DNA to Public does not independently make it eligible for Discover.

Do not share a DNA as publicly discoverable until the product shows the necessary status.

#### A7. Write down the success condition

Define a realistic success condition before starting.

For a Full Production DNA, it might be a clearly organized primary profile with available models or track references you can inspect.

For Voice DNA, it might be a completed voice model visible in My DNA.

Do not use an uncertain outcome, such as a guaranteed public listing, fixed earnings, or an exact output, as the only definition of success.

### Playbook B: Prepare a Full Production DNA catalog

Use this path when the goal is a continuing, catalog-based primary DNA.

#### B1. Choose representative catalog material

Select authorized songs, instrumentals, or acapellas that represent the sound you want the primary DNA to learn.

The catalog does not need to contain every piece of music you have ever made.

It should be intentional enough that you can explain the shared creator, project, or musical direction.

Avoid turning the upload area into an unreviewed file dump.

#### B2. Remove accidental duplicates and irrelevant versions

Review the selected files before upload.

Keep a version only when it has a clear reason to be part of the training source, such as an authorized instrumental or a distinct approved arrangement.

Repeated copies of the same export can make your project harder to audit later.

The product does not promise that duplicate versions create extra models, tracks, or earnings.

#### B3. Check the actual audio, not only the metadata

Play each file in a trusted local player before upload.

Verify that it is the intended recording, an accepted audio format, and not a corrupted file, silent file, document, archive, image, or video renamed as audio.

Use a known-good authorized source when a file is damaged or cannot be identified.

Keep the original local source until upload and processing status are clear.

#### B4. Account for collaborators and samples

Review material that contains co-writers, producers, session players, featured artists, sampled works, label-controlled masters, or licensed third-party assets.

Your participation in a project does not necessarily mean you have all permissions required for DNA training.

Resolve questions before upload rather than trying to fix rights after a public or payment-related outcome.

This guide cannot determine rights for a particular track or agreement.

#### B5. Keep the catalog understandable

Use a simple grouping such as a project era, production identity, a creator catalog, or a deliberate sound direction.

You can include more than one genre when it honestly belongs to the same creator or catalog context.

If the selections are unrelated, consider whether the goal needs a clearer source plan before you process them together.

The actual processing result remains dependent on the content that was supplied.

#### B6. Prepare a clear profile

Use a recognizable creator or project name, short accurate description, relevant tags, and authorized cover art.

The current description field has a limit, so concise factual language is usually more useful than marketing claims.

Cover art helps people recognize a profile, but it does not replace the uploaded audio as a processing source.

Do not use another person's name, identity, branding, image, or work in a misleading way.

#### B7. Document the selected sensitivity

Full Production DNA uses a sensitivity control in the Process DNA step.

The current UI uses a 0 through 10 range and provides a balanced default.

Write down the value you choose and why you chose it. This lets you make a meaningful comparison after the result is available.

Sensitivity does not compensate for unclear rights, incomplete uploads, or a catalog that does not represent the intended sound.

#### B8. Start processing once

Wait until the upload has completed and the product reports it is ready to process.

Use Process DNA once for the active request.

The current flow intentionally blocks duplicate starts while processing is already underway.

Do not open additional tabs or repeat clicks in an attempt to force a second run.

#### B9. Review the actual result

Return to My DNA after processing has had time to complete.

Review the primary DNA, models, tracks, and available references that the product actually shows.

A later upload and processing run adds to the current primary DNA; it does not create a second primary Full Production profile for the same owner.

Do not promise a fixed model count, track count, or generation capability before you inspect the result.

### Playbook C: Prepare a Voice DNA dataset

Use this path when the goal is a dedicated model for one authorized voice.

#### C1. Confirm the single-voice rule

Choose one speaker or singer for one Voice DNA training request.

Do not mix singers, speakers, background voices, conversations, choirs, or unrelated vocalists into one intended voice dataset.

If you have several voices, plan separate authorized source sets and use the current product options for each.

The presence of a vocal recording does not by itself prove it is suitable for Voice DNA.

#### C2. Prefer clear solo-vocal source audio

Use recordings where the intended voice is audible and not competing with background music, heavy effects, crowd noise, or other voices.

The current guide recommends aiming for about 10 minutes of usable clean solo-vocal audio.

One recording can satisfy the basic form requirement, but a useful dataset should match the training goal rather than merely satisfy a minimum control.

Do not expect a specific result from duration alone.

#### C3. Keep source privacy in mind

Review whether a recording includes personal conversations, other people, addresses, passwords, financial information, health information, or confidential project details.

If it does, prepare a cleaner authorized recording specifically for the Voice DNA purpose.

Do not upload private audio simply because it contains a usable voice sample.

Use a secure support channel only when support specifically asks for private material.

#### C4. Confirm consent honestly

The current Voice DNA flow requires a consent confirmation before training can begin.

Confirm only if the voice is yours or you have the speaker's or singer's consent to clone it.

Consent is not inferred from a public recording, a social media clip, a celebrity voice, or a casual collaboration.

If consent is unclear, stop and resolve it before continuing.

#### C5. Choose a quality setting intentionally

Voice DNA uses an epoch-based quality control instead of Full Production sensitivity.

The current range is 10 to 350 epochs, with Fast at 10, Balanced at about 180, and Studio at 350.

Read the current duration and token estimate before starting. They are estimates, not a promise of a particular completion time or result.

The balanced default is a reasonable first choice when you do not have a source-specific reason to choose another value.

#### C6. Check the state before retrying

Voice DNA can show Queued, Preparing, Training, Completed, or Failed.

Queued means waiting for capacity; Preparing means the dataset is being processed; Training means epoch progress is available.

Do not submit duplicate training requests while an existing request is in an active state.

When Failed appears, read the visible message and correct a real source, consent, or configuration problem before retrying.

#### C7. Review the completed profile

Completed means the current training result reports completion.

Open My DNA or View in your profile to inspect the actual resulting voice model and available controls.

The completed state does not independently promise public listing, every generation style, commercial rights, or revenue.

Use the model and control state actually displayed to decide how to continue.

### Playbook D: Use a DNA in generation

Use this path when a DNA, model, or reference is already available.

The selected DNA, model, reference, output style, prompt, lyrics, and current product behavior can all affect a result.

If it is clean, solo-vocal, authorized, and intended to train one person's voice, it may fit the Voice DNA goal.

If it is a catalog asset with layered vocals, effects, or broader song context, it may fit Full Production DNA instead.

The correct choice is based on the training goal and source content, not the word acapella in the file name.

### Scenario 4: My upload stops midway

Keep the same authorized source files available.

Read the visible error and retry through the product. The current Full Production uploader can reuse a valid session and confirmed chunks when possible.

Do not start a different project, make random duplicate files, or repeatedly click Process DNA before upload readiness is confirmed.

If the issue persists, report the file count, formats, visible error, approximate time, and DNA flow involved.

### Scenario 5: Process DNA is unavailable

Check whether the upload is complete and marked ready.

Check whether a previous Full Production processing run is still active.

The current flow blocks duplicate processing starts intentionally.

If the visible state does not explain the problem, capture the status and error text before contacting support.

### Scenario 6: I expected a new primary DNA after another upload

The current Full Production workflow maintains one primary DNA profile per owner.

Later authorized uploads and processing runs add to that existing primary profile instead of creating a second primary Full Production DNA.

Open My DNA and look for the existing primary profile, its new models, tracks, or processing state.

Do not create duplicate requests merely to obtain a second primary profile.

### Scenario 7: I do not see a new Full Production model

Check whether processing is still active and inspect the primary DNA after it completes.

The product does not promise that every catalog produces multiple new visible style models or references.

Review the actual models and tracks available in My DNA, not just an expected name or notification.

If it remains missing, report the source flow, visible status, approximate time, and non-sensitive upload details.

### Scenario 8: Voice DNA remains Queued

Queued means the current training request is waiting for available capacity.

It is different from a Failed state and does not provide a reliable completion countdown.

You can close the window and return later to check the profile state.

Avoid starting a duplicate request while the original one remains queued.

### Scenario 9: Voice DNA reports Failed

Read the exact visible status and return to the DNA Quality step as the product directs.

Check the source audio, single-voice requirement, consent confirmation, file formats, and selected epoch value.

Make an intentional correction before retrying instead of repeatedly submitting the same failing request.

Include non-sensitive details and the visible error if you need support.

### Scenario 10: A generation control is missing

Check the selected DNA, model, track reference, and output style.

Generation controls are context-aware, so another available selection can show different valid options.

The current request contract supports Song and Instrumental. A vocal reference does not create a universal standalone vocal option.

Use only the controls enabled for the current selection.

### Scenario 11: My Full Production DNA is not in Discover

Check both visibility and moderation status.

For the current Full Production public-discovery path, the DNA must be Public and Approved.

Pending, Private, Personal, Rejected, and On hold do not meet that condition.

Do not promise a public discovery result until the product shows the required state.

### Scenario 12: Stripe Connect does not open

Read the error displayed by the Earn page.

The connection flow requires a Stripe Connect URL returned by the service and a configuration that matches the current Stripe mode.

Record the approximate time, whether the account was already linked, and the visible error before retrying.

Never paste Stripe credentials, cookies, or secret headers into a support message.

### Scenario 13: A creator has earnings but has not connected Stripe

The protected ledger can record a verified paid DNA export or Fan Support earning before the creator completes Stripe onboarding.

The history can show Pending Stripe connection or Payout setup required.

The creator should use Connect Stripe and complete the current setup and verification requirements.

The balance will not become an immediate bank transfer solely because the account was connected later.

### Scenario 14: A balance is below the payout threshold

Read the current minimum payout threshold shown in Earn. The current default is $50 USD unless the account summary provides a different amount.

Keep tracking verified earnings in the ledger and avoid assuming that a smaller protected balance will be transferred immediately.

The balance also needs to be eligible after protection and the Stripe account needs to be ready.

Use the account's Next payout date and status for current information.

### Scenario 15: Earn says Not scheduled

The balance may still be in payment protection, below the threshold, awaiting Stripe setup, or on an account where automatic payouts are disabled or unavailable.

Read the balance cards, history status, minimum threshold, and Stripe account state together.

Do not attempt to manually move money based on an unscheduled balance.

Use the current product message as the account-specific guide.

### Scenario 16: A payment is refunded or disputed

The corresponding creator earning can move to Payment review or show a reversal.

The current creator balance can decrease as the payment provider's event is reconciled.

This is part of the protected earnings design and is why a payment record is not automatically equivalent to a final bank payout.

Check the affected history row and contact support with non-sensitive details if the adjustment is unclear.

### Scenario 17: Fan Support says the conversation is unavailable

Make sure you are using the actual eligible conversation with the intended recipient.

The product verifies the conversation and recipient relationship rather than accepting an arbitrary person supplied from the browser.

Do not try to support yourself or modify browser data to target a different recipient.

If the conversation is valid but the message continues, record the conversation context, visible error, and approximate time for support.

### Scenario 18: I am testing in sandbox mode

Use only the test Connect and Checkout flow provided by the test environment.

Test funds can validate the Earn ledger and history, but test payouts are disabled and cannot be withdrawn as real money.

Keep test and live accounts, checkout sessions, and expectations separate.

Confirm the visible Stripe mode before interpreting any test outcome.

### Scenario 19: I need to explain DNA to a collaborator

Use plain status language: catalog DNA, voice model, upload ready, processing, training, Pending, Approved, protected earnings, or payout setup required.

Do not promise exact model behavior, public availability, ownership, payout amount, or timing that the product has not confirmed.

Share only information you are authorized to share, especially where source audio and voice consent are involved.

Point collaborators to the appropriate My DNA, Discover, or Earn state rather than a vague claim.

### Scenario 20: I need to contact support

Start with the affected surface: Full Production DNA, Voice DNA, generation, Discover, paid export, Fan Support, Stripe Connect, or Earn.

Include the exact visible error, current status, approximate time and timezone, and non-sensitive context such as the file count or payment source type.

Keep raw private audio, passwords, session cookies, API keys, Stripe credentials, bank details, and full card data out of an ordinary support message.

Use a secure support channel only when the support team explicitly asks for sensitive material.

## Part 13: DNA and earning glossary

Use this glossary when a status or product term is unfamiliar.

The definitions describe the current product behavior and should be read together with the visible account state.

### Acapella

An acapella is audio centered on vocals without the full instrumental arrangement.

It can be catalog material for Full Production DNA. It is suitable for Voice DNA only when it is a clean solo-vocal recording of one authorized voice.

### Approved

Approved is the moderation status required together with Public visibility for the current Full Production Discover path.

It is not a payout approval, a commercial-rights statement, or a promise of earnings.

### Artist share

Artist share is the portion of a verified payment reserved in the creator earnings ledger for the relevant creator or Fan Support recipient.

The current policy reserves 50% of a gross paid DNA export and 75% of a gross verified Fan Support payment.

### Available model

An available model is a processed DNA model shown by the product for a selected DNA.

It can be used as a broader Model Based starting point only when the current product makes it selectable.

### Balance card

A balance card summarizes a part of the protected creator-earnings ledger, such as current creator balance, eligible after protection, or in payment protection.

It is not automatically a bank balance or an instruction to withdraw money.

### Become Partner

Become Partner is an Advanced Options configuration presented in the current Full Production flow.

Use the current product wording and applicable terms to understand it; do not treat the label alone as a payout or earnings guarantee.

### Completed

Completed means the current Voice DNA training result reports completion.

Inspect My DNA to see the actual voice model and current available controls.

### Creator earnings ledger

The creator earnings ledger records protected creator shares from paid DNA exports and Fan Support payments.

It tracks earnings and payout status separately from the immediate Stripe or bank cash balance.

### Current creator balance

Current creator balance is the protected ledger amount after known adjustments.

It can include amounts that are still in payment protection or awaiting payout setup, and it is not a promise of immediate withdrawal.

### Discover

Discover is the product area for browsing DNA content that is eligible for public discovery.

It is separate from My DNA and depends on current visibility, approval status, and product availability.

### DNA model

A DNA model is a processed result associated with a DNA profile.

When available, it can provide a broader creative context for Model Based generation.

### Fan Support

Fan Support is a Stripe support payment from one person to a creator in an eligible conversation.

The recipient's 75% creator share is recorded as a protected earning after payment verification.

### Full Production DNA

Full Production DNA is the catalog-based flow for authorized songs, instrumentals, and acapellas that represent a broader musical identity.

It uses a primary DNA profile and a sensitivity control for catalog processing.

### Generation style

The current DNA request contract supports Song and Instrumental generation styles.

The appearance of a vocal reference does not create a universal standalone vocal generation style.

### In payment protection

In payment protection is the portion of a creator balance still held during the applicable payment-protection period.

It is recorded but not yet eligible for payout.

### Ledger unavailable

Ledger unavailable means the product cannot currently read the protected creator-earnings ledger.

The product intentionally avoids presenting that condition as a zero balance because zero would be misleading.

### Model Based

Model Based uses an available DNA model as a broader creative starting point for generation.

The current selection determines which output styles and controls are available.

### Money accrued

Money accrued is the running total of creator earnings recorded in the ledger.

It can include amounts that have not yet been paid out.

### Money paid

Money paid is the running total recorded as paid through the creator payout lifecycle.

It does not include all currently protected or eligible creator earnings.

### My DNA

My DNA is the primary management area for your DNA profiles, models, tracks, and voice models.

Use it as the product source of truth after a processing or training request completes.

### Next payout date

Next payout date is the account-specific payout date shown by Earn when a schedule is available.

It is not a guaranteed bank-arrival time.

### On hold

On hold is a moderation status that is different from Approved.

Public visibility does not bypass an On hold state for current public discovery.

### Payment review

Payment review indicates that a source payment is being reviewed after an event such as a refund or dispute.

The creator amount can be adjusted or reversed while that review is resolved.

### Payment protection

Payment protection is the period in which a verified creator earning is held before it becomes payout-eligible.

It helps account for later payment-provider events such as refunds or disputes.

### Pending

Pending is a Full Production moderation status that has not reached the Approved state required for current public discovery.

It is not the same as a Stripe payment status or Voice DNA training status.

### Pending Stripe connection

Pending Stripe connection means the creator earning is recorded but the recipient has not yet completed connection of a payout account.

The amount can remain in the ledger until payout setup is ready.

### Personal

Personal is a current Full Production visibility choice used to keep the DNA outside the public-discovery path.

It is distinct from moderation approval and from a private commercial agreement.

### Private

Private is a visibility choice that keeps a DNA outside the current public-discovery path.

It does not erase the source, replace rights obligations, or independently control every product record.

### Public

Public is a Full Production visibility choice for DNA intended to be considered for public availability.

For the current Discover path, the DNA must also be Approved.

### Payout processing

Payout processing means a payout is being processed against the creator earnings ledger.

It is later distinct from the Paid status that records completion.

### Payout setup required

Payout setup required means the earning is recorded but Stripe connection, verification, banking, or another payout prerequisite needs attention.

Use the current Stripe setup information to understand the account-specific next step.

### Paid

Paid means the creator payout lifecycle has recorded a payout as completed.

Use Stripe and the receiving bank for account-specific availability information.

### Paid DNA export

Paid DNA export is an earning source recorded when a buyer completes a verified export payment for eligible paid DNA audio.

The current creator policy reserves 50% of the gross purchase payment for the DNA creator before later adjustments.

### Primary DNA profile

The primary DNA profile is the ongoing home for a creator's catalog-based Full Production DNA.

Later authorized catalog uploads and processing runs add to that profile rather than creating a second primary Full Production profile.

### Queued

Queued is a Voice DNA training state that means the request is waiting for available capacity.

It is not a Failed result and does not provide an exact completion timer.

### Ready for payout

Ready for payout means the ledger considers a creator amount eligible after payment protection.

It still needs a ready Stripe account, the relevant threshold, and an available payout path.

### Rejected

Rejected is a moderation status different from Approved.

Changing visibility alone does not bypass a Rejected status for public discovery.

### Reversal

A reversal is an adjustment to a recorded creator earning after a verified refund, dispute, or other payment-provider event.

It can reduce the current creator balance and affect a future payout.

### Song

Song is one of the current DNA generation styles.

The exact input controls still depend on the selected DNA, model, or track reference.

### Stripe Connect

Stripe Connect is the payout-account onboarding flow available through Earn.

It can be required before creator earnings can be sent as a payout, but connecting Stripe does not itself guarantee payout timing or eligibility.

### Test mode

Test mode or sandbox mode uses Stripe test objects and test funds to validate the flow.

Test payouts are disabled and do not send real money to a bank account.

### Track Based

Track Based uses a specific available song, vocal, or instrumental reference as a more focused generation starting point.

The reference type does not guarantee every output style or control.

### Track reference

A track reference is a processed audio reference associated with a DNA profile.

It can appear as song, vocal, or instrumental context in the generation experience.

### Training

Training is the Voice DNA state where the product reports training progression, such as current and total epochs.

It is different from Queued, Preparing, Completed, and Failed.

### Voice DNA

Voice DNA is the voice-focused flow for clean solo-vocal recordings of one authorized speaker or singer.

It uses an epoch-based quality control and can attach a trained voice model to the current primary profile.

### Voice DNA quality

Voice DNA quality is the epoch setting selected before voice training begins.

The current range is 10 to 350 epochs, with Fast, Balanced, and Studio guidance in the product.

### Voice model

A voice model is the completed result of a Voice DNA training request when the product reports it as available.

It is different from a vocal track reference and does not promise every possible vocal output capability.
